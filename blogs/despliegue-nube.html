Mi Viaje con el Despliegue en la Nube: De Novato a DevOps

15 de Octubre, 2023 12 min de lectura

Recuerdo mi primer despliegue en producción como si fuera ayer: un simple sitio HTML subido por FTP a un hosting compartido. Hoy, después de implementar más de 50 proyectos en la nube, quiero compartir contigo las lecciones que he aprendido en este viaje de transformación hacia las prácticas DevOps.

Mi Evolución en el Despliegue

  1. Etapa FTP (2020): Subir archivos manualmente con FileZilla
  2. Hosting Compartido (2021): cPanel y problemas de compatibilidad
  3. VPS (2022): Mis primeros comandos SSH y configuración manual
  4. Plataformas como Servicio (2023): Descubriendo Heroku y Vercel
  5. Infraestructura como Código (2024): Terraform + AWS
  6. CI/CD Automatizado (2025): Git push para despliegue automático

Mi Stack Actual de Despliegue

Después de probar múltiples soluciones, este es mi setup actual para proyectos:

Aplicaciones Estáticas (React, Vue)

  • Plataforma: Vercel
  • Ventajas: Integración con GitHub, previews para PRs
  • Costo: Gratis para proyectos personales

Lecciones Aprendidas (Por las Malas)

Mi experiencia con la nube incluye algunos errores que espero puedas evitar:

💸 La Factura de $500 por un Bucket Público

En 2023 configuré mal un bucket S3 que permitía tráfico ilimitado. En una semana tuve una factura enorme por transferencia de datos. Solución: Ahora siempre uso CloudFront delante de S3 con límites de gasto.

🌐 Downtime Durante un Lanzamiento

Al actualizar mi portafolio sin estrategia de despliegue, causé 15 minutos de inactividad. Solución: Implementé blue-green deployments con AWS.

🔒 Exposición de Credenciales

Subí accidentalmente un archivo .env a GitHub. Solución: Ahora uso secretos gestionados y git-secrets para prevenir commits peligrosos.

Mi Flujo CI/CD Actual

Para mis proyectos serios, he estandarizado este proceso:

  1. Desarrollo: Feature branches en GitHub
  2. Pruebas: GitHub Actions ejecuta tests
  3. Revisión: Preview en Vercel para cada PR
  4. Despliegue en Staging: Merge a develop branch
  5. Pruebas Finales: Smoke tests automatizados
  6. Producción: Deploy con canary releases
# Parte de mi workflow de GitHub Actions
name: Deploy to Production

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
        
      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: 18
          
      - name: Install dependencies
        run: npm ci
        
      - name: Build project
        run: npm run build
        
      - name: Deploy to AWS
        uses: aws-actions/configure-aws-credentials@v1
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: us-east-1
          
      - name: Deploy with CloudFormation
        run: aws cloudformation deploy --template-file template.yml --stack-name my-app

Consejos para Empezar

Si estás comenzando con despliegue en la nube, esto es lo que me hubiera gustado saber:

  • Empieza con servicios gestionados: Vercel/Netlify para frontend, Heroku para backend
  • Automatiza desde el principio: Aunque sea con scripts básicos
  • Monitorea todo: Configura alertas tempranas
  • Documenta tus despliegues: Especialmente configuraciones especiales
  • Prueba la recuperación: Simula fallas regularmente

El despliegue en la nube ya no es un lujo sino una necesidad. Dominar estas herramientas me ha permitido entregar proyectos más robustos, escalables y profesionales. ¿Tienes preguntas específicas sobre tu flujo de despliegue? ¡Contáctame y con gusto te ayudo!
